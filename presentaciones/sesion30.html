Errores comunes

Criterios de Rechazo del Hito 3

Estos son los puntos de falla que la verificación de hoy está diseñada para detectar.

Antipatrones que debes evitar

  • API vulnerable a SQL Injection o que utilice consultas crudas concatenadas con cadenas.
  • Fallas de consistencia transaccional (datos huérfanos o commit parcial tras una excepción).
  • Incapacidad de ejecutar las migraciones de base de datos desde cero en una instancia limpia.

Cómo lo comprueba el cuaderno

  • Crear un libro persistente HTTP 201
  • Listar los libros persistidos HTTP 200
  • La búsqueda resiste inyección HTTP 200
  • CORS autoriza el origen permitido HTTP 200
  • El healthcheck responde HTTP 200
  • Hay persistencia real
No se evalúa cómo escribes el código: se evalúa el comportamiento que el cliente observa.

RESUMEN: 5/5 casos correctos. ¡Hito 3 listo!

Lo que debe cumplirse

  • Los libros se guardan en SQLite y sobreviven al reinicio.
  • La búsqueda usa consultas parametrizadas.
  • CORS permite https://app.ejemplo.com.
  • GET /health responde 200 con status ok.
  • Los cinco casos del hito deben quedar en verde.
5 casos + 2 comprobaciones en el verificador. Sin pasos intermedios: tú decides la estructura.
