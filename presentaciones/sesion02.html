Fundamentos

Semántica del Protocolo HTTP y Métodos de Petición

El protocolo HTTP define acciones estandarizadas sobre recursos identificables mediante verbos con semántica de idempotencia y seguridad.

01. GET & DELETE (Lectura y Baja)

GET recupera una representación del recurso sin alterar su estado; DELETE remueve la entidad.

Ambos deben ser idempotentes: múltiples peticiones idénticas producen el mismo estado en el servidor.

02. POST vs PUT / PATCH (Creación vs Edición)

POST crea recursos subordinados con ID generado por el servidor; PUT reemplaza totalmente el recurso; PATCH realiza modificaciones parciales.

POST no es idempotente (múltiples POST crean múltiples recursos).

03. Código HTTP 405 Method Not Allowed

Respuesta emitida cuando la URI existe pero el verbo HTTP utilizado no está implementado en la ruta.

Debe incluir el encabezado 'Allow' informando los métodos aceptados.

Idempotencia en APIs REST

Garantía de que reintentar una petición fallida por problemas de red no corromperá el estado de la base de datos.

Esencial para construir clientes web resilientes.
Errores comunes

Antipatrones en Métodos HTTP

Estos son los puntos de falla que la verificación de hoy está diseñada para detectar.

Antipatrones que debes evitar

  • Usar GET para modificar o eliminar datos en el servidor (ej. /api/eliminar_usuario?id=5), rompiendo la seguridad del protocolo.
  • Usar POST para todo (Antipatrón 'RPC sobre HTTP') ignorando la semántica de PUT, PATCH y DELETE.
  • Retornar HTTP 200 OK en respuestas de error de método no permitido.

Cómo lo comprueba el cuaderno

  • La colección inicia vacía HTTP 200
  • POST crea el libro con id 1 HTTP 201
  • GET lista el libro creado HTTP 200
  • GET por id encuentra el libro HTTP 200
  • PUT reemplaza el libro HTTP 200
  • DELETE elimina el libro HTTP 204
No se evalúa cómo escribes el código: se evalúa el comportamiento que el cliente observa.
El reto de hoy: resultado final

Tu CRUD de libros responderá exactamente así

así se verá el resultado
$ curl -X POST http://127.0.0.1:8000/api/libros \
       -H "Content-Type: application/json" \
       -d '{"titulo":"Cien años de soledad","anio":1967}'
HTTP/1.1 201 Created
{"id":1,"titulo":"Cien años de soledad","anio":1967}

$ curl http://127.0.0.1:8000/api/libros
HTTP/1.1 200 OK
{"libros":[{"id":1,"titulo":"Cien años de soledad","anio":1967}]}

$ curl -X PUT http://127.0.0.1:8000/api/libros/1 \
       -H "Content-Type: application/json" \
       -d '{"titulo":"Cien años de soledad (edición conmemorativa)","anio":1967}'
HTTP/1.1 200 OK
{"id":1,"titulo":"Cien años de soledad (edición conmemorativa)","anio":1967}

$ curl -X DELETE http://127.0.0.1:8000/api/libros/1
HTTP/1.1 204 No Content

Lo que debe cumplirse

  • GET /api/libros responde 200 con {"libros": [...]}.
  • POST /api/libros responde 201 con el libro creado y un id asignado por el servidor.
  • GET /api/libros/{id} responde 200 con el libro o 404 si no existe.
  • PUT /api/libros/{id} reemplaza el libro y responde 200; DELETE responde 204 sin cuerpo.
  • Un verbo no implementado sobre una ruta existente debe responder 405, no 404.
